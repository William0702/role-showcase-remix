# 项目内技术缓存

v1.8.1 默认在 `.remix/cache` 保存可重新计算的技术数据，不改变配额、制作审批、画面/声音阈值及独立语义审阅要求。

## 元数据与帧时间戳

渲染器的源片段、兼容媒体和待核验成片按实际文件 SHA256、FFprobe 二进制内容、解析代码及本包版本缓存完整探测结果。每次访问仍读取当前文件哈希；不以同名、大小或修改时间相同判断内容未变。改变内容、解析代码或工具会重新探测；损坏记录退回实际探测。探测期间文件变化会拒绝结果。

缓存是技术探测结果，不能说明角色身份或对白已被理解。入库与全帧语义审阅仍按原流程执行。

## 原生导出与交付

`filmcraft-export` 对没有相符证据的成片执行原有全部输出帧、真实源首末帧、双声道零时移及音频长度核验，只有成功结果能生成复用记录。

`filmcraft-deliver` 在当前成片、全部源片段、顺序与裁尾、完整方案、输出参数与阈值、工程、兼容媒体、FilmCraft CLI、FFmpeg/FFprobe、验证代码和包版本都匹配时，复用该次完整技术结果；仍检查当前文件、工程、媒体哈希和配额，不再为同一内容重复生成完整比较素材。旧版仅有 `passed=true` 的报告没有完整绑定，不能据此复用。

证据中的 `validation_cache.status` 为 `miss`、`hit`、`forced` 或 `bypassed`，记录实际走过的路径。成功证据首次生成前后重新检查绑定，检测计算中变化。强制复检先撤销旧的通过证据，失败或异常不得恢复旧 PASS。缓存摘要只检测意外损坏，不是数字签名，也不证明缓存目录遭恶意伪造后的真实性。

交付已有原生成片时若本机没有可用 FilmCraft CLI，不为缓存身份识别安装软件，而是跳过验证缓存、执行完整 FFmpeg 技术核验，保留原有离线交付能力。

## 强制复检与排障

- `filmcraft-export --force-recheck` 或 `filmcraft-deliver --force-recheck`：重做完整画面和双声道技术核验；按内容校验的元数据仍可复用。
- 现有 `verify` 命令保持完整验证，不因存在原生验证缓存而跳过。
- 环境变量 `REMIX_DISABLE_CACHE=1`：本次进程同时禁用元数据和验证证据缓存，执行原探测与完整技术验证。恢复环境变量后缓存重新按绑定条件检查。
- 缓存损坏/丢失或不可写时退回计算，缓存不作为制作必需依赖。强制复检若无法撤销已有证据则明确失败，不能继续保留旧 PASS 冒充新检查。
- `.remix/cache/events.jsonl` 记录命中/未命中/强制复检。可清理派生缓存来回收空间；不得删除审批、源清单、方案、成品或 usage 账本来绕过核验。

缓存不代表人工核听、独立角色判断或成片定稿。成品首尾及全部接点仍应实际查看；无核听能力时如实保留缺项。

强制复检会先撤销当前输出相关的所有验证缓存，即使同时禁用缓存或本机无 FilmCraft CLI；失败或异常后恢复缓存也不得复用旧通过证据。
