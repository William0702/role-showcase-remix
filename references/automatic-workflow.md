# 问答后自动制作：默认入口

## 使用者只提供视频

用户上传本地视频、多个视频附件或母片文件夹路径即可。Agent读取可访问的真实附件路径；附件不可读取时仅询问缺失文件或可访问路径。Agent在当前允许写入的工作区建立独立批次目录，建议“混剪制作_日期_批次”，主动报告路径；用户已指定目录时优先使用。不要要求使用者先建母片、工程或表格，不把安装目录作制作目录，不使用历史测试目录。保留原文件，自动复制入库、整理目录和清单。

执行前使用doctor --full与filmcraft-doctor；按software-workflow.md自动检查、安装并自检完整FilmCraft。随包FilmCraft CLI可headless制作，即使用户没有启动GUI也可生成原生.fcproj及视频。实际使用原生编辑与导出，不把仅由FFmpeg输出的文件称为FilmCraft导出。原生GUI或桥接不是自动批量运行的前提；不更改用户正在编辑的桌面项目。

## 问答规则

直接在聊天里问，不把JSON配置或工具命令交给用户填写。每轮最多三项，能合并为同一决定的放在一起；答案写入项目内.remix/intake-answers.json。只问未明确项，引用当前实际素材和已有用户选择，不重复问。默认是自动执行；若用户明确要求逐步确认，才使用旧展示流程的逐步停点。

推荐问答顺序：

1. 模式：完整角色展示重排，还是剧情前段接后段？能从明确请求确定就跳过；不明确可先看素材再给建议。
2. 展示规则：每条3或4个角色、本批条数或按配额尽可能多做、每片段上限及配额范围。原母片归属是否限制、相同集合是否允许等有需求时补充；默认允许同母片不同片段，单条不重复，集合不重复，次数是上限不是用满。
3. 输出：画幅/分辨率/帧率、保留原声、不加音乐。可把推荐规格作为完整选项一次询问，不逐个追问宽、高。
4. 命名：自动编号即可，还是指定业务规则？选择自动编号不追问ID或来源名字；指定时一次收齐ID、素材名、分类、来源标签、原母片名字字段规则及后缀。来源名字无法从文件准确提取时才补问对应关系。

用户已经说“自动完成”或“按这些规则制作”时，该真实授权连同问答结果覆盖一致的切分、排列、原生导出和命名，不再问“是否开始”，也不在每张区间表、方案、样片、命名表后停下来索要同一授权。没有自动制作授权时，只补问一次执行方式。未回答必要问题、等候超时或技能文本均不当作授权。

Agent用auto-intake验证问答；status=questions_pending时向用户展示missing questions的自然语言，收到真实答案后更新并再次验证。不要自动填虚构回答。运行规格和权限异常需明确说明：当前auto-produce只实现展示类、保留原声的本批统一配额；跨批累计先汇总账本并明确剩余额度，不能把累计改成本批。剧情按原独立模块执行，其FilmCraft决定表映射尚未成为已验证的自动命令，不向用户承诺同等一键能力。

## 自动准备和实际拉片

新目录运行init，复制本批原视频到母片，建立路径记录和来源映射；inventory锁定源哈希、数量、帧率、重复和原声。问答可在入库过程中进行，不依赖答案的工作继续推进。

review生成完整帧页，Agent必须实际查看全部帧。同一角色换景别/动作/变身保持一段，边界用全尺寸相邻帧核对，移除真正无角色的纯文字尾巴。写segments.json及审阅记录，普通边界不再等待用户审批。只有身份不确定、边界不能判断、需要牺牲完整动作或句子等具体疑问才提出问题，并展示对应证据；可明确处理的其余素材继续整理。

没有实际看完、工具不能看图、素材损坏或问题未解决时，不写完成标记。完成后创建.remix/automation.json：

```json
{
 "intake_sha256": "实际intake.json哈希",
 "segments_sha256": "实际segments.json哈希",
 "visual_review_complete": true,
 "unresolved": []
}
```

此标记由执行Agent对实际审阅负责，工具的布尔检查不能证明语义审阅。自动识别仍依赖使用技能的Agent，不是安装器独自推理视频角色。

## 自动技术制作

```powershell
& "技能目录\run.cmd" auto-intake --project "本批目录"
# Agent完成实际全帧审阅、清单及无歧义检查点后
& "技能目录\run.cmd" auto-produce --project "本批目录"
```

auto-produce验证问答与边界绑定，依据用户真实提前授权记录cut；切分；按规则生成plan并审计；记录同一提前授权的render；兼容素材生成；FilmCraft原生时间线和原声轨拼接；FilmCraft原生导出；独立核验并自动登记最终成品；按指定命名规则自动命名；再次verify与生成技术交付记录。自动编号模式无需改名审批或追问ID。

问答JSON结构：mode=showcase，group_size=3或4，target_count=正整数或capacity，max_uses=正整数，quota_scope=batch，output_width/output_height=实际偶数，output_fps=实际分数帧率，preserve_original_audio=true，naming=generic或custom，authorization_text=本次真实自动授权原文。custom另外填写id_prefix、material_name、category、tag、fixed_suffix、size_label。Agent维护这些字段，不要求用户理解内部参数。用户有明确搭配偏好时，另外记录distinct_sources、unique_sets、unique_pairs、balance_positions或exact_uses的真实布尔决定；不把上限解释为用满。来源名字需补充时Agent写入项目内映射文件，回答结构可用author_map指定其项目相对路径。选择capacity时先按配额和不重复集合等组合上界计算条数；复杂约束仍可能造成有界搜索失败，此时说明实际冲突，不声称已证明全局最大条数。

原声、首末和每片段全部输出帧沿用现有阈值，不因自动化放宽。兼容素材另存，原母片和切片保留。原生交付写入rendered/usage，样片、改名、修订和再运行都不多算次数。已有对应工程及已校验视频可复用；哈希变化、未验证同名文件、已完成批次问答变化时不覆盖或悄悄重置账本。

自动技术链完成不等于最终内容检查完成。Agent逐条实际查看成品首尾及所有接点，并保存检查记录。发现可明确修复的技术问题自主定位、保留问题版、修复后重新导出检查；语义不能确定或超出问答授权的实质规则变化才问用户。未能实际核听时写“原声技术通过，听感未独立试听”，不能伪称声音已人工验收。

## 最终交付

直接给最终可播放成品、FilmCraft工程及其媒体目录、排列方案、配额统计、命名对照（指定命名时）与检查报告的完整路径。说明实际条数、每片段次数、检查范围及未解决项，不以“方案已生成”代替出片。工程依赖兼容媒体，移交需一并保留，迁移后检查路径重链接。

## 成片后补充音频问答

最终原声成片可播放后，按post-export-audio.md主动询问本批是否去BGM、保留环境音效与人物念白，或先分析再决定。auto-produce生成待确认音频记录，Agent在实际内容查看后向用户提问。原版照常交付，未回答不修改音轨。

## 用户成片定稿与可选第二阶段

第一阶段交付不视为用户已批准定稿。先确认具体成片是否满意并可定稿，再询问是否制作英雄定格；需要时按[英雄定格完整流程](hero-freeze-workflow.md)及其逐项确认推进。该模块包含样张、三类资产及两路动画提示词。auto-produce不会自动生成这些图或提示词，执行Agent须实际完成而非只写状态标记。第一阶段自动授权不跳过第二阶段门槛。

## 需要停下来问的例外

以下例外针对第一阶段，第二阶段另遵守其用户确认节点。仅在素材不可访问、角色/剧情边界证据不足、数量与配额冲突、来源名字不明影响指定命名、需要改变已确认规则或工具确实无法完成时询问具体缺口。先提供实际证据或可选解决方案。已有任务授权的目录整理、普通技术修复和通过核验的自动拼接无需重复征求许可。
