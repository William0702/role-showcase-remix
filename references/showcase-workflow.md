# 展示类混剪模块

默认自动模式按[问答与自动制作](automatic-workflow.md)执行，下列逐步确认停点仅用于用户明确选择分步审阅的模式；不据此重复索取已经提供的全流程自动授权。

仅在用户选择展示类模式时读取。本模式以完整角色展示作为排列单位。

先读取 [操作及参数](operations.md) 和 [确认与质量规范](workflow.md)。以下组大小、次数和命名规则只适用于该模式，不自动传递到剧情模式。

## 执行步骤

1. **收取素材和配置。** 用户把视频放入项目 `母片`，或指定另一个项目内源目录。`init` 创建配置，`inventory` 建立内容哈希、帧数、时间戳、原声和命名来源清单。列出实际母片数量、异常和重复内容。按确认规范锁定组大小、批量数量、最多使用次数及其他规则；已有明确授权不重复问。
2. **完整拉片，先不切。** 每个母片执行 `review`，查看所有编号帧页，登记完整角色区间。同一角色换景别、动作和变身保留为一个展示；切镜不是角色边界的充分条件。疑似边界执行 `review --boundary` 查看全尺寸相邻帧，明确末角色帧和下角色首帧。输出 `.remix/segments.json` 与角色区间说明，请用户确认边界方案。未实际看完全部帧不得声称完整拉片。
3. **切分样片并校准。** 用户确认后，记录 `cut` 审批并用 `cut --only` 切一个典型母片的片段。检查首尾图片、完整角色、纯文字/黑屏尾巴、原声和自动技术报告。展示样片供用户确认标准。随后批量 `cut`，每个母片单独放入 `切分/<母片ID>/`。不覆盖原母片。
4. **排列和样片。** 全部合格片段作为统一池，按确认规则执行 `plan`、`plan-audit`。用户要先看一条时先出该条明确片段顺序；记录该方案 `render` 审批后 `render --only 01`。样片计入最终批次。如需保留样片顺序，把其 ID 序列写进 `fixed_videos` 再生成最终方案。不要把样片额外算作一条或额外使用次数。
5. **完整方案确认和渲染。** 展示每条顺序、源母片、角色、总使用次数、位置统计及约束报告。直接用户授权与当前方案对应后记录 `render` 审批；批量 `render`。原声音轨跟随各片段，按实际帧边界裁音；不加音乐。相同已验证文件断点续作。`verify` 独立校验实际输出，逐条查看开头、所有拼接点及末尾画面；技术检查通过不能代替内容审阅。
6. **修订。** 仅尾部无角色文字时，列出真实源末尾帧范围、受影响成品及修订方案，经授权记录 `revise` 审批，使用 `revise` 从片段源重新渲染并保留备份。多个成品共用问题片段时先列影响范围，逐条决定；不能仅修一个就声称全部合格。其他内部边界错误回到角色区间方案，更新、确认并重建受影响文件。
7. **命名和交付。** `naming` 先出完整旧名→新名对照。名字取原母片文件中的来源名字字段，按混剪片段出现顺序去重；首段对应来源首先出现。统一 ID、素材名、分类、后缀等由本批确认，不能把历史 `id310` 写死。用户确认后记录 `rename` 审批并 `rename`，再次 `verify`，交付成品、完整方案、使用统计、审阅与技术报告。
8. **增量批次。** 新母片先独立入库和逐帧审阅；旧哈希/已验证片段可复用。确认使用上限是本批还是跨批累计；新批使用独立项目或先冻结上一批账本。禁止把旧配额悄悄清零。
