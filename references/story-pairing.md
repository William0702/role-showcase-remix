# 全池内容索引、A/B 筛选与样片模板

只在剧情模式、且本次素材池和目标明确时读取。阶段顺序与授权见 [共创蓝图](story-collaboration.md)，实际切点和剪法见 [剧情模块](story-montage.md)。以下记录由 Agent 维护，用户无需填写 JSON；前台先看白话剧情、关键画面、方案对照和分歧。

## 1. 先理解全池，再索引

完整查看每条纳入素材，核实人物、事件、诉求、对白、前因后果与结果、动作、情绪、A/B 实际边界、真实画面区域和音轨。文件标签仅辅助定位，不从“A面/B面”目录或名称直接推定内容。完整片必须理解全片后，才判断前后段及可用范围，不沿用原成片组合当作唯一配对。

|字段|记录要求|
|---|---|
|源身份|稳定源 ID、文件映射、SHA256；重复内容和完整片拆出区间保留来源关系|
|内容理解|人物及指代、事件顺序、诉求、承诺对象、原因和结果、动作/情绪；事实/推断/疑点分别给依据|
|区间证据|0 基帧区间、真实 PTS、关键画面，视觉与声音入出点分别记录|
|原声与字幕|完整话语、原字幕及音效功能、时间可信程度、实际听音范围；疑词回源核对|
|叙事功能|提出问题/诉求、做选择、采取行动、给答案或结果、角色/玩法说明等实际功能|
|使用条件|需要什么前文、指代依赖谁、不可拆的整句和动作、合法入口/出口、未兑现的信息|
|画幅与声音|编码尺寸之外的实际内容区、包装/三栏/字幕/人物位置；音轨组成与切点限制|
|审阅状态|已查看/未查看范围、证据限制、独立纠正、用户确认版本及未解决项|

索引先覆盖全池再给配对。无法读取的素材逐条标记，不跳过后宣称完整理解；必要时请用户确认排除范围。关键疑点未解决的条目不进入推荐制作池，不影响已审清内容的记录整理。

## 2. 全池寻找关系，严格筛选

对本次 A/B 合法池进行内容筛选，不局限原配、不只围绕已选 A 找证明。不是要求穷举成品或每个源强行使用：输出候选列表、排除类别与覆盖情况；必要时单独说明某素材为什么无合理搭配。

优先寻找可陈述且可取证的承接关系，例如具体诉求→具体解答、角色选择→对应玩法、行动→合理结果。主题/画风相近、游戏类型一致、对白无直接冲突只是辅助信号，不足以单独列为强推荐。

逐组先问：A 让观众期待什么？B 实际提供什么？是否换了诉求/承诺对象、人物或产品功能？需要观众凭空补哪些信息？B 若只适合作产品介绍，不能把它解释成 A 剧情结果的兑现。项目中某一版本获认可，也不让这种解释自动成立于其他组合。

|配对项|方案必须说明|
|---|---|
|身份与区间|候选 ID、A/B 源 ID/哈希、合法池、区间和版本|
|关系证据|A 收束的完整句/动作与未完成期待、B 入口的实际信息；具体如何延续/回应/转换|
|完整成片概述|按最终播放顺序讲清观众看到与听到什么，不仅分别概括两段|
|顺剪方向|保持 A 原顺序的保留/删减、对白整句、动作收束、B 入口及必要声音处理|
|蒙太奇方向|明确改善悬念/因果揭示/情绪/节奏的目标，与顺剪对比，拟重排和保护条件；不成立写不适用与原因|
|否决与未知|指代偷换、承诺落空、因果矛盾、语气/动作断裂、情绪突变、声音/画幅不可兼容及未核听事项|
|结论|可提样片、需修后再议、待补证、淘汰；独立意见和用户选择分别保留|

对同组素材提供两个方向的分析，不等于强制生产两版。不能为了交出蒙太奇，把一段连续短口播拆开倒序，再用转场遮掩气口和动作断裂。若没有具体改善，保留顺序或请求其他素材；不要把“无需重排”伪装成成功蒙太奇。

## 3. 样片前完成画幅与音画方案

检查“编码尺寸”和“真正叙事内容区域”是否相同；三栏横版可能包含中央竖屏剧情，不能机械缩整幅塞进竖屏。提取区域、裁切、等比放大、留边或重新构图的选择先给用户看证据和方案；逐个核对人物、对白字幕、底部说明、重要道具与运动轨迹。不能套固定裁切坐标到所有素材，也不强制所有横版都裁成竖版。

ASR 全文时间仅初选，锁剪点要核对源音分窗、气口/尾字、真实画面帧与当前实际输出；一次整段时间偏移要追查受影响区间。没有实际听音能力就标未核听并交用户检查，不能靠相关度或响度填通过。

样片清单列代表的规则/画幅类型、原素材与输出参数、A 和 B 上下文、内部接点、最终接点、构图与声音处理、预期效果、失败后退路和待用户判断项。保留足够内容检验节奏，不能只给一两秒静态接缝就认定整片成立。

## 4. 批量前的适用判断与定点反馈

样片通过后，对每个待制作候选填写：采用哪条已认可规则、为什么适用、是否存在新叙事/构图/声音例外。新规则先出方案与代表样片，不把例外混入批量授权。规则只作用于本项目已确认范围，不成为其他用户默认要求。

当前审片入口逐条显示：候选 ID、当前版本、父版本、状态（待审/认可/需修/淘汰）、播放路径、使用规则、五类验收、独立问题、用户原文与具体认可范围。未评价不算认可，一句整体回复不扩成未明确的听音报告；技术通过也不能把淘汰改回认可。认可项保留，旧版可回溯，只有受影响条目返修。
